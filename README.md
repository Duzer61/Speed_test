# speed-test

Скрипт-замерятель скорости интернета. Принимает адрес (URL тяжёлой картинки или
файла), **последовательно** выполняет 10 запросов (по умолчанию), дожидается
полного ответа, а затем печатает в консоль среднее время запроса, объём
скачанных данных и среднюю скорость скачивания в МБ/с.

## Требования

- Python 3.13+
- [uv](https://docs.astral.sh/uv/) (зависимости зафиксированы в `pyproject.toml` / `uv.lock`)
- Библиотека `requests` (подтягивается командой `uv sync`)
- Docker с плагином Compose — только для запуска через `docker compose`
  (см. раздел «Запуск в Docker»)

## Запуск

```bash
uv sync                      # при необходимости установить зависимости

uv run main.py http://spd-rudp.hostkey.ru/files/10mb.bin    # адрес аргументом
uv run main.py                                              # адрес будет запрошен в консоли
uv run main.py speedtest.selectel.ru/10MB                   # без схемы -> подставится https://
```

## Запуск в Docker

```bash
docker compose build        # собрать образ speed-test
docker compose up           # запускает замер по адресу по умолчанию (10 МБ × 10 запросов)

# свой адрес — переменной окружения (или строкой SPEED_TEST_URL=... в файле .env)
SPEED_TEST_URL=speedtest.selectel.ru/100MB docker compose up

# адрес и флаги main.py — аргументами после имени сервиса
docker compose run --rm speed-test http://spd-rudp.hostkey.ru/files/10mb.bin -n 5
docker compose run --rm speed-test speedtest.selectel.ru/10MB -q

# адрес спрашивается в консоли (как `uv run main.py` без аргументов)
docker compose run --rm --entrypoint python speed-test main.py
```

Как это работает:

- `docker compose up` сразу запускает `main.py` с адресом по умолчанию
  (`http://spd-rudp.hostkey.ru/files/10mb.bin` из таблицы ниже). Другой адрес задаётся
  переменной `SPEED_TEST_URL` — командой (см. пример) или строкой в `.env` рядом с
  `docker-compose.yml`. После замера контейнер завершается, а `docker compose up`
  возвращает код возврата скрипта: `0` — замер удался, `1` — ни один запрос не прошёл.
- Аргументы после имени сервиса полностью перекрывают команду сервиса и дописываются к
  `ENTRYPOINT ["python", "main.py"]`, поэтому доступны все опции скрипта:
  `-n/--count`, `-t/--timeout`, `--no-cache-bust`, `-q`.
- Ввод адреса вручную (`--entrypoint python … main.py`) работает благодаря `stdin_open: true`
  в `docker-compose.yml`; прогресс «Запрос 1/10 …» печатается построчно
  (`PYTHONUNBUFFERED=1` в `Dockerfile`). Именно `run` (а не `up`) используется для интерактива:
  `docker compose up` stdin в контейнер не прокидывает, поэтому там замер стартует сразу
  по адресу из `SPEED_TEST_URL`.
- Зависимости внутри образа ставятся командой `uv sync --frozen` строго по `uv.lock`,
  запуск идёт от непривилегированного пользователя `app`.
- Замер выполняется с сетевого стека контейнера (bridge + NAT). На Linux, чтобы исключить
  NAT и получить самый «честный» результат, можно раскомментировать в `docker-compose.yml`
  строку `network_mode: host` (в Docker Desktop на macOS/Windows этот режим не работает).
- Подсказки интерактивного меню `compose` («w Enable Watch / d Detach») в выводе можно
  убрать: `COMPOSE_MENU=0 docker compose up`.

## Готовые адреса для замера (доступны из РФ, без VPN)

Проверено с российского провайдера (Ростелеком, Ростов-на-Дону):

| Адрес | Размер файла | Комментарий |
| --- | --- | --- |
| `http://spd-rudp.hostkey.ru/files/10mb.bin` | 10 МБ | Hostkey (Москва, LibreSpeed) — основной вариант, только по `http://` |
| `http://spd-rudp.hostkey.ru/files/100mb.bin` | 100 МБ | то же, для быстрых каналов; есть также `1000mb`, `2000mb`, `5000mb`, `10000mb` |
| `https://speedtest.selectel.ru/10MB` | 10 МБ | Selectel — альтернатива |
| `https://speedtest.selectel.ru/100MB` | 100 МБ | Selectel; есть также `/1GB` и `/10GB` |
| `https://mirror.yandex.ru/ubuntu-releases/22.04/ubuntu-22.04.5-live-server-amd64.iso` | ~1.9 ГБ | зеркало Яндекса — для очень быстрых каналов |
| `https://mirror.truenetwork.ru/ubuntu-releases/22.04/ubuntu-22.04.5-desktop-amd64.iso` | ~3.9 ГБ | зеркало Truenetwork |

Все адреса проверялись так же, как их запрашивает скрипт (с параметром обхода
кэша `?_cb=...` и заголовком `User-Agent: speed-test/0.1`) — отвечают `200 OK`.
Помните, что за один замер скачивается `запросов × размер файла` (по умолчанию
10 × 10 МБ ≈ 100 МБ): для медленного канала берите файл на 10 МБ, для
гигабитного — 100 МБ и больше. У зеркал путь к ISO привязан к версии
дистрибутива и со временем меняется — актуальную версию берите в листинге
каталога (например, <https://mirror.yandex.ru/ubuntu-releases/>).

Про схему: серверы Hostkey отдают файлы по `http://`, а `https://` у них не
проходит TLS-рукопожатие из Python (`SSLV3_ALERT_HANDSHAKE_FAILURE`), поэтому для
них схему `http://` нужно указывать явно. У остальных адресов таблицы `https://`
работает — например, `speedtest.selectel.ru/10MB` без схемы автоматически
превращается в `https://speedtest.selectel.ru/10MB`.

## Опции

| Опция | Описание | По умолчанию |
| --- | --- | --- |
| `url` | адрес для замера; если не указан — запрашивается в консоли | — |
| `-n`, `--count` | число последовательных запросов | `10` |
| `-t`, `--timeout` | таймаут одного запроса, секунды | `30` |
| `--no-cache-bust` | не добавлять параметр обхода кэша `_cb=...` | выключено |
| `-q`, `--quiet` | печатать только итоговую статистику | выключено |

## Коды возврата

| Код | Когда возвращается |
| --- | --- |
| `0` | замер выполнен, есть хотя бы один успешный запрос |
| `1` | ни один запрос не завершился успешно |
| `2` | некорректный адрес или адрес не был введён |

Код можно проверить через `$?` и использовать в условиях оболочки:

```bash
uv run main.py example.com/file.bin || echo "замер не удался, код: $?"
```

Это делает скрипт пригодным для `&&`/`||`, `if` и CI (`set -e`).

## Как считается результат

- **Время запроса** — от старта запроса до полного вычитывания тела ответа
  (`time.perf_counter()`); отдельно показывается TTFB (время до первого байта).
- **Объём** — реально прочитанные байты (чтение чанками по 64 КиБ), а не значение
  заголовка `Content-Length`.
- **МБ/с** — `скачано МБ / суммарное время`, где 1 МБ = 1024² байт.
  Дополнительно выводится скорость в **Мбит/с** (10⁶ бит) — в этих единицах
  обычно оперируют провайдеры.
- Все запросы идут через одну `requests.Session`, поэтому TCP/TLS-соединение
  переиспользуется (keep-alive) и рукопожатие не искажает замер.
- Чтобы ответы не отдавались из кэша CDN, к каждому запросу добавляется
  уникальный параметр `_cb=<время>` и заголовки `Cache-Control: no-cache`,
  `Pragma: no-cache`. Отключается флагом `--no-cache-bust`.

## Тесты

```bash
uv run python -m unittest discover -s tests -v
```

Тесты поднимают локальный HTTP-сервер на `127.0.0.1` и не требуют интернета.

## Замечания

- Результат ограничен пропускной способностью сервера-источника и канала между
  вами и им, поэтому может отличаться от замеров Speedtest.
- Сбои отдельных запросов не прерывают замер: они печатаются как предупреждения
  и исключаются из статистики. Если не удался ни один запрос, скрипт завершается
  с кодом возврата `1` — остальные коды описаны в разделе «Коды возврата».
- Популярные зарубежные тест-файлы (`speed.hetzner.de`, `speedtest.tele2.net`,
  `ipv4.download.thinkbroadband.com`) из России недоступны или отдают `403`,
  поэтому в примерах используются российские адреса — см. раздел
  «Готовые адреса для замера».
